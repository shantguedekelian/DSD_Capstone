# DSD Capstone (D42)

DSC 180 capstone (D42) with the City of San Diego Development Services Department (DSD). It analyzes how many review cycles (resubmittals) permit applications go through, and includes a prototype permit-readiness checker.

> The data is a raw, unvalidated DSD extract, provided for research use only. Everything here is preliminary and is not an official City or DSD finding.

## Setup

1. Install [uv](https://docs.astral.sh/uv/getting-started/installation/).
2. Clone the repo and create the environment:

```bash
git clone https://github.com/shantguedekelian/DSD_Capstone.git
cd DSD_Capstone
uv sync
```

`uv sync` reads `pyproject.toml` and `uv.lock`. It uses Python 3.13 (from `.python-version`; the project requires `>=3.12`) and installs JupyterLab, which is in the dev dependency group.

## Reproducing the analysis

Put the data in `data/` first (see Data access). The first code cell of each notebook finds the repo root, so you can run them from the repo root or from `notebooks/`.

| Run order | Notebook | Reads | Writes |
|---|---|---|---|
| 1 | `notebooks/01_reviews_target.ipynb` | `data/02_Data/Activity_Tables/DSD_Reviews_2026-10-19.csv` | `data/processed/review_cycles.csv` |
| 2 | `notebooks/reviews_eda.ipynb` | same reviews file | `figures/01_…png` to `figures/06_…png` |
| 3 | `notebooks/basic_eda.ipynb` | `data/approvals_created_2025_datasd.csv` | nothing |
| 4 | `notebooks/eda_summary.ipynb` | `data/approvals_created_2025_datasd.csv` | nothing |

Only notebook 1 feeds the app. The other three do not depend on each other.

Run interactively in JupyterLab:

```bash
uv run jupyter lab
```

Or use VS Code (or any editor that opens `.ipynb` files):

1. Install the Python and Jupyter extensions.
2. Open the repo folder and open a notebook from `notebooks/`.
3. Click **Select Kernel** (top right) and pick the `.venv` that `uv sync` created, then **Run All**.

Or run one notebook from the command line:

```bash
uv run jupyter nbconvert --to notebook --execute notebooks/01_reviews_target.ipynb
```

This writes the executed copy to `notebooks/01_reviews_target.nbconvert.ipynb`. That file is git-ignored, so you don't need to delete it when you are done.

## Permit readiness prototype (Streamlit app)

**This is a prototype that only runs locally.** It is not deployed. It is guidance only, not an official DSD determination.

What it does:
- You upload a filled-out application (PDF or .txt).
- The app checks it against `data/checklist.json`, a draft checklist built from public DSD bulletins, using the Gemini API.
- It shows a completeness score, the checklist items found, missing or unclear, and a table of historical resubmittal rates by discipline for the permit type you pick.

Privacy: the first 30,000 characters of the uploaded text are sent to Google's Gemini API. Do not upload real applicant information.

To run it yourself:

1. Get a free Gemini API key from Google AI Studio: https://aistudio.google.com/apikey
2. Create your `.env` and put the key in `GEMINI_API_KEY`. Never commit `.env`.

   ```bash
   cp .env.example .env
   ```

3. Optional: add `GEMINI_MODELS` to `.env` as a comma-separated list of model names from AI Studio, for example `GEMINI_MODELS=modelA,modelB`. Gemini models change often and can return 503 under load. The app tries the models in order (two attempts each) and moves on when one fails. The defaults are in `user_helper_prototype/app.py`.
4. Make sure `data/checklist.json` exists (it is in git) and `data/processed/review_cycles.csv` exists (run notebook 1 first).
5. Start the app **from inside `user_helper_prototype/`**. It reads `../data/...` relative to the working directory, so it fails if started from the repo root.

   ```bash
   cd user_helper_prototype
   uv run --env-file ../.env streamlit run app.py
   ```

   Streamlit prints a local URL (http://localhost:8501 by default).

## Limitations

- **Data:** raw, unvalidated extract with known quality issues (duplicates, negative durations, "undefined" for missing values; see the handoff PDF). Not for operational decisions.
- **No review-comment text:** the reviews table has cycle numbers and outcomes (for example "Recheck Required"), not what reviewers asked for. The app can show how often a discipline sends a permit type back, but not why.
- **Checklist is a draft:** it is marked `DRAFT - needs DSD staff review`. It covers one scenario (garage conversion to ADU, single-family), built from four DSD documents (IB 400, IB 140, IB 122, and the building permit guide). Its quotes have not been fully verified against the source PDFs.
- **The score is completeness only:** it compares an application to the draft checklist. It does not predict whether reviewers will ask for a resubmittal.
